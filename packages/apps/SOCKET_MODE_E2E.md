# Socket Mode E2E testing matrix

This matrix validates the exclusive inbound Socket Mode transport using deterministic Jest coverage and focused testing with a real Teams client, classic bot registration, and local sample app.

Socket Mode starts no HTTP listener, public HTTP messaging endpoint, fallback transport, or composite adapter. The internal `HttpServer` still registers its messaging route with `SocketModeAdapter`, where registration is intentionally a no-op. Inbound socket activities are dispatched directly through the shared `App.onActivity(...)` pipeline with an internally synthesized connection-authenticated token. Outbound replies and sends continue through the conversation API.

`Validation` identifies the primary test boundary:

- **Jest** — deterministic SDK behavior using controlled connections, envelopes, timers, and adapters.
- **Teams** — behavior that depends on the real Teams client, APX routing, Azure SignalR, or service-generated activity shapes.
- **Hybrid** — deterministic assertions belong in Jest, with a focused live smoke test in Teams.

`Passed` records completed deterministic Jest validation. `Jest passed` records the deterministic portion of a Hybrid row; its Teams evidence remains pending. Teams-only rows intentionally remain blank.
